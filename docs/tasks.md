## 2. テストケース定義 (TDD 用)

### ユニットテスト

#### テストケース 1: メモリストア - メッセージの追加と取得

- **目的**: 会話履歴が正しく保存・取得できることを確認
- **前提条件** (Given):
  - 空のメモリストア
  - チャンネルID "test-channel"
- **操作** (When):
  - ユーザーメッセージを追加
  - アシスタントメッセージを追加
- **期待結果** (Then):
  - 2件のメッセージが取得できる
  - メッセージの順序が保持されている

#### テストケース 2: メモリストア - 最大件数の制限

- **目的**: 20件を超える履歴が正しく制限されることを確認
- **前提条件** (Given):
  - 空のメモリストア
- **操作** (When):
  - 25件のメッセージを追加
- **期待結果** (Then):
  - 最新の20件のみが保持される
  - 古い5件は削除されている

#### テストケース 3: Gemini クライアント - 正常な応答

- **目的**: Gemini API への正常なリクエストと応答処理
- **前提条件** (Given):
  - モックされた Gemini API クライアント
  - 会話履歴
- **操作** (When):
  - GenerateResponse を呼び出し
- **期待結果** (Then):
  - 175文字以内の応答が返る
  - エラーが発生しない

#### テストケース 4: Discord ハンドラー - メンション検出

- **目的**: ボットへのメンションを正しく検出
- **前提条件** (Given):
  - Discord メッセージイベント
  - ボットID "bot123"
- **操作** (When):
  - "@bot123 こんにちは" というメッセージ
- **期待結果** (Then):
  - 応答処理が実行される
  - メンションが除去されたテキストが処理される

#### テストケース 5: メモリストア - ギルド間の分離

- **目的**: 異なるギルドの会話履歴が混在しないことを確認
- **前提条件** (Given):
  - 空のメモリストア
  - ギルドA のチャンネル "channel-a"
  - ギルドB のチャンネル "channel-b"
- **操作** (When):
  - ギルドA のチャンネルにメッセージを追加
  - ギルドB のチャンネルにメッセージを追加
- **期待結果** (Then):
  - ギルドA の履歴を取得時、ギルドA のメッセージのみ取得
  - ギルドB の履歴を取得時、ギルドB のメッセージのみ取得
  - 各ギルドの会話履歴が完全に分離されている

#### テストケース 6: エラーハンドリング - API エラー

- **目的**: Gemini API エラー時の定型文応答
- **前提条件** (Given):
  - Gemini API がエラーを返す設定
- **操作** (When):
  - メッセージ処理を実行
- **期待結果** (Then):
  - 定型文が Discord に送信される
  - エラーがログに記録される

### 統合テスト

#### シナリオ 1: 基本的な会話フロー

- **目的**: エンドツーエンドの会話処理
- **テストフロー**:
  1. Discord からメンション付きメッセージ受信
  2. Gemini API で応答生成
  3. Discord に応答送信
  4. 会話履歴の更新
- **期待結果**:
  - 適切な応答が送信される
  - 会話履歴が保持される

## 3. リスクと対策

### 技術的リスク

| リスク         | 影響度 | 発生確率 | 対策                                   |
| -------------- | ------ | -------- | -------------------------------------- |
| メモリ不足     | 高     | 中       | 会話履歴の上限設定、定期的なメモリ監視 |
| API レート制限 | 中     | 低       | エラー時の定型文応答、使用量の監視     |
| Discord 接続断 | 高     | 低       | 自動再接続、Docker の restart policy   |

### スケジュールリスク

| リスク                | 影響度 | 発生確率 | 対策                         |
| --------------------- | ------ | -------- | ---------------------------- |
| Gemini API の仕様変更 | 中     | 低       | インターフェースによる抽象化 |
| テスト作成の遅延      | 中     | 中       | TDD の徹底、モックの活用     |
