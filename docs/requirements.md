# Chatbot 要件定義書

## 1. 背景と目的

### 背景

コミュニティサーバーで使用するシンプルなDiscord用AIチャットボットが必要である。将来的には高度な記憶機能をデータ構造の整理により実現したいが、まずは基本的な会話機能から開始する。

### 目的

- Discord サーバーでメンバーと自然な会話ができるAIチャットボットを提供する
- 段階的に機能を拡張できる基盤を構築する
- 無料枠（GCE e2-micro）で安定動作するシステムを実現する

## 2. 機能要件

### バージョン1.0（MVP）- 基本的な会話機能

#### ユーザーストーリー

- As a Discord ユーザー, I want ボットにメンションして会話する so that AIと対話できる
- As a Discord ユーザー, I want ボットのメッセージに返信する so that 会話を続けられる
- As a サーバー管理者, I want /reset コマンドを使う so that 会話をリセットできる

#### 機能詳細

1. **会話応答機能**
   - 説明: ユーザーのメッセージに対してAIが応答
   - 入力:
     - ボットへのメンション付きメッセージ
     - ボットのメッセージへの返信
   - 出力: Gemini APIを使用した自然な応答（175文字以内）
   - 処理: メモリ内で直近20件の会話履歴を保持

2. **コマンド処理**
   - `/reset`: 現在のチャンネルの会話履歴をクリア
   - 将来追加予定: `/character [name]` - キャラクター切り替え

### バージョン2.0（計画）- 永続化と拡張機能

#### 追加機能

1. **会話履歴の永続化**
   - Firestoreへの会話履歴保存
   - 過去の会話の参照機能

2. **キャラクター管理**
   - 複数のキャラクター定義
   - ギルドごとのキャラクター選択

## 3. 非機能要件

### パフォーマンス

- レスポンスタイム: 3秒以内（95パーセンタイル）
- 同時接続数: 10ギルドまで
- メモリ使用量: 512MB以内（e2-microの制限）

### 可用性

- 稼働率: ベストエフォート（無料枠のため）
- エラーハンドリング: 定型文での応答
  - API エラー時: 「申し訳ありません。現在応答できません。しばらくしてからお試しください。」
  - その他のエラー: 「エラーが発生しました。管理者にお問い合わせください。」

### 運用環境

- インフラ: GCE e2-micro インスタンス
- OS: Container-Optimized OS
- コンテナ: Docker

## 4. 制約事項

### 技術的制約

- 言語: Go
- AI API: Google Gemini API（無料枠）
- データベース: Firestore（バージョン2.0から）
- Discord ライブラリ: discordgo

### リソース制約

- CPU: e2-micro（0.25-2 vCPU）
- メモリ: 1GB
- Gemini API: 無料枠の制限内
- Firestore: 無料枠の制限内（1GB、読み取り5万回/日、書き込み2万回/日）

### 運用制約

- 24時間365日の稼働保証なし
- 自動スケーリングなし
- バックアップは手動
